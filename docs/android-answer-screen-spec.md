## 1. 界面结构树

```
题目屏（单页，上下两段固定 + 中段滚动）
├── 状态栏（系统）34dp
├── 顶部信息区 72dp
│   ├── 进度环 46dp（本轮完成度，环内显 3/5）
│   ├── 本轮题号「第 3 / 5 题」+ 统计「答对 2 · 答错 1 · 正确率 67%」
│   ├── 筛选图标按钮 34dp → 唤起筛选抽屉
│   └── 规律提示图标按钮 34dp → 题面卡内展开提示
├── 进度条 3dp（下边距 12dp）
├── 中段内容区（可滚动，隐藏滚动条）
│   ├── 题面卡（自适应高度）
│   │   ├── chip 行：模式（随机练习/间隔复习/错题重练）· 词条类别 · 目标形式（橙色强调）
│   │   ├── 词条大字 40sp + 读音 12.5sp
│   │   ├── 释义 14sp
│   │   ├── 指令 13.5sp「请选出「て形」的正确形态」  ← 判定后隐藏
│   │   └── 提示按钮 + 提示面板                      ← 判定后隐藏
│   └── 选项组（4 项，纵向整宽，间距 9dp）
└── 底部判定抽屉（固定，含上提阴影）
    ├── 收起态 76dp：已选答案状态 + 「确认提交」按钮
    └── 展开态 241dp（实测）：判定标题 + 正确形态 + 读音 + 你的答案 + 大意 + 解析 + 「下一题」
└── 底部导航 64dp
```

## 2. 纵向分区规格（dp）

| 分区 | 高度 | 内边距 | 说明 |
|------|------|--------|------|
| 状态栏 | 34 | 左右 20 | 系统绘制 |
| 顶部信息区 | 72 | 左右 18 | 进度环 46 + 两行文本 + 两个 34dp 图标按钮 |
| 进度条 | 3 | 左右 18，下 12 | 底 `--line-faint`，进度 `--green`，圆角 999 |
| 题面卡 | 自适应 ≈196（判定后 ≈150） | 内 15 | 判定后隐藏指令与提示、字号 40→34 |
| 选项 | 每项 57（单行）/ 自适应（两行） | 内 13×14 | 间距 9 |
| 判定抽屉 | 收起 76 / 选中 89 / 展开 241（上限 46% 屏高） | 内 10×18 | 上圆角 18，上提阴影 |
| 底部导航 | 64 | 左右 8 | 4 等分 |

**合计校验**：812（典型屏高）− 34 − 72 − 15 − 64 − 241（抽屉展开）= 386dp 留给题面卡 + 选项组；
实测判定后有 **4/4 个选项完整可见**（题面卡压缩后），无需滚动即可看到揭晓的正确项。

## 3. 区块规格

### 3.0 顶部统计卡（口径以已确认规格为准）

顶部区是**纸白卡**（`--surface` + 1dp `--line` + 轻阴影，圆角 16dp），卡内自左至右：进度环 46dp · 题号与统计两行 · 筛选图标 · 辅助开关图标；卡内底部通栏 3dp 进度条。

| 项 | 口径 |
|----|------|
| 进度环 / 进度条 | = **当前题号 ÷ 本轮题数**；**判定后不前进**，进入下一题才推进 |
| 第一行 | 「第 n / N 题」（n = 当前题号，判定后不变） |
| 第二行 | 「答对 x · 答错 y · 正确率 z%」，x/y/z 均为**本轮累计**；分母为 0 时显示「—」 |
| 更新时机 | 判定后**仅**第二行立即更新；环与进度条保持不动 |
| 一致性 | 第二行的 x/y/z 与抽屉内「本轮小结」使用同一公式，两处数字必须一致 |

> 全周期累计统计（历史答对/答错）仍在 `AppState` 中持久化，供主页使用；顶部卡只呈现本轮。

### 3.1 题面卡

| 元素 | 规格 | 规则 |
|------|------|------|
| 模式 chip | 11.5sp / 内距 5×9 / 圆角 999 / 底 `--bg-pale-green` 字 `--text-strong` | 三态文案：随机练习、间隔复习、错题重练 |
| 类别 chip | 同上，底 `--green-pale` 字 `--green-dark` | 例：动词 · 五段、形容词 · な |
| 目标 chip | 同上，底 `--orange-pale` 字 `--orange-deep`，**加粗** | 例：て形、过去否定 — 全卡唯一暖色，抓视线 |
| 词条大字 | 40sp / 700 / 楷体 / 字距 +0.02em | 判定后缩至 34sp 让位 |
| 读音 | 12.5sp / `--reading` | **受「显示规律提示」按钮统一控制**（与提示面板同显同隐）；隐藏时显示灰色占位「假名」；**判定后强制显示**（见 §4.5） |
| 释义 | 14sp / `--meaning` | 超长可折行；超过 2 行截断加省略（详情不做展开） |
| 指令 | 13.5sp / `--text-strong` | **判定后隐藏**（信息已进入抽屉，避免重复） |
| 提示 | 12.5sp 虚线面板 / 底 `--bg-pale-green` | 与假名同一按钮控制；判定后隐藏；同一题再次点击收起 |

### 3.2 选项组

| 状态 | 边框 | 底色 | 序号块 | 右侧图标 | 可点 |
|------|------|------|--------|----------|------|
| 默认 | 1.5dp `--line` | `--surface` | 纸底 + `--line-control` 描边 | 无 | 是 |
| 按下 | 1.5dp `--line-accent` | `--bg-pale-green` | 同上 | 无 | 是 |
| **已选中（未判定）** | 1.5dp `--green` | `--green-pale` | 绿底白字 | 无 | 是（可改选） |
| **正确** | 1.5dp `--green` | `--green-pale` | 绿底白字 | 勾（绿） | 否 |
| **错误** | 1.5dp `--red` | `--red-pale` | 红底白字 | 叉（红） | 否 |
| **正确答案揭晓** | 1.5dp **虚线** `--green` | `--surface` | 纸底 | 勾（绿） | 否 |

- 序号为 1–4 数字，26dp 方形、圆角 8dp；两行文本时序号与文字**顶端**对齐（`align-items: flex-start` + 2dp 视觉补偿）。
- 颜色 + 图标 + 边框样式**三重冗余**：色觉障碍下仍能区分「我选错的」与「正确答案」。
- 选项文本两行以内不截断；超过两行按字符级省略（词库实际不会出现）。

### 3.3 底部判定抽屉

**形态（2026-10-15 关子裁决）：固定底栏**——抽屉是常驻屏幕底部的浮动面板，不随内容滚动。

| 备选形态 | 裁决 | 理由 |
|----------|------|------|
| **固定底栏（采用）** | ✅ | 「下一题」常驻拇指可及区，连续刷题不必滑到底；当前解析均为单句（如「一段动词去る接ます」），241dp 内放得下，无嵌套滚动负担 |
| 解析插入内容流（作为块接在选项下方） | ❌ 本轮不采用 | 优势仅在解析很长时显现（多步变换/对比表），词库当前无此形态；若日后出现长解析可重估 |

两条配套约束（由固定底栏形态派生，必须同时成立）：

1. 判定后**题面卡压缩**（隐藏指令与辅助按钮、大字 40→34sp），把高度让给选项区——否则底栏长高会挤掉一个选项；
2. 判定后**自动把正确项滚入视野**（`bringIntoView`），保证答错时能看到揭晓位置。

未判定时的「已选答案 + 确认提交」栏同样固定底部（两步式的提交入口不能随内容滚走）。

**收起态（76dp，选中后 89dp 实测）**：左侧两行状态（`尚未作答 / 请选择一个答案` 或 `已选答案 / 読んで`），右侧「确认提交」主按钮；
未选择时按钮**禁用**（底 `--bg-pale-strong`、字 `--muted`）。
选中后状态区第三行给出 11sp 灰色提示「再次点击该选项可直接提交」（见 §4.3 快捷路径）。

**展开态**：内容优先序固定如下，解析过长时抽屉内部滚动（上限 46% 屏高，可上滑全展至 70%）。

| 序 | 内容 | 规格 |
|----|------|------|
| 1 | 判定标题 | 15sp / 700；答对 `--stat-correct` + 勾，答错 `--stat-incorrect` + 叉 |
| 1' | 错题 chip（仅答错） | 同排右对齐，11sp / 底 `--orange-pale` / 字 `--orange-deep`「已加入错题本」 |
| 2 | 正确形态 | 20sp / 700 |
| 3 | 读音 | 12sp / `--reading` |
| 4 | 你的答案 | 12.5sp / `--text-strong` |
| 5 | 语态 / 形式大意 | 12sp / `--text-strong` |
| 6 | 变化规则（解析） | 12.2sp / 行高 1.65；上虚线分隔；关键术语（「あ段」「拨音便」等）加粗 `--green-dark` |
| 7 | 下一题 | 主按钮，通栏 |

**判定后视口策略**（原型实测结论）：抽屉展开会压缩内容区，因此判定后立即把**正确项滚入可视范围**（`scrollIntoView(block=nearest)`），保证答错时用户能看到揭晓位置。

## 4. 交互流程与状态机

### 4.1 两步式作答（本方案核心）

```
①选择 ──▶ ②确认提交 ──▶ ③判定着色 + 揭晓 ──▶ ④抽屉展开解析 ──▶ ⑤下一题
```

| 步骤 | 用户动作 | 界面响应 |
|------|----------|----------|
| ① 选择 | 点任一选项 | 该选项进入「已选中」态；抽屉栏从左变「已选答案：X」、「确认提交」变可用，并显示双击快捷提示 |
| ① 改选 | 点另一个选项 | 选中态转移，无副作用（**两步式的核心收益**） |
| ①' **双击加速** | 同一选项 300ms 内再点一次 | 直接提交判定（等效于「确认提交」），见 §4.3 |
| ② 提交 | 点「确认提交」 | 选项锁定，按 §3.2 着色；正确项揭晓 |
| ③ 判定 | 自动 | 统计 / 题号即时刷新；答错则错题入本（沿用加权 + 间隔复习） |
| ④ 解析 | 自动展开 | 抽屉展开，正确项滚入视野 |
| ⑤ 下一题 | 点「下一题」 | 出新题（到期错题优先 → 洗牌题池），抽屉回落收起态 |

**Q3 裁决：答对后不自动跳转**。判定成立后停留在当前题（抽屉展开、选项锁定、正误着色），必须由用户点「下一题」推进。理由：答对时用户同样需要看规则与读音；自动跳会把解析一闪而过。实现上不引入任何延时跳转定时器。

**Q5 裁决：Web 端不同步**。选择题只在 Android 落地，Web 保持现有输入式不受影响（`web/` 全量 82/82 基线不动）；两端状态互不同步，各自独立存储（Android `filesDir` / Web `localStorage`），不做任何跨端打通。

**为什么用两步式**：选择题有四个大热区，一步式（点选即判）在单手/晃动的场景下误触率不低，一次误触直接判错并进错题本，代价过高；两步式用一次低成本点击换取**可改选 + 防误触**，且让抽屉的「提交」职责名副其实。

### 4.2 状态机

```
idle ──选择──▶ picked ──确认──▶ judged ──下一题──▶ idle
  ▲               │                 │
  └───改选────────┘                 └──（错题重练模式下累计 reviewed 集合）
idle/picked/judged 均可点提示、开筛选抽屉（不丢当前题状态）
judged 后点第 5 题完成 → roundEnd（本轮小结）
```

### 4.3 双击直接提交（快捷路径）

**交互定义**：相邻两次点击落在**同一选项**且间隔 < 300ms → 第 1 击选中、第 2 击**直接提交判定**（与「确认提交」走同一条判题路径，保证状态一致）。

| 项 | 规格 | 实测结论（原型 Playwright 断言） |
|----|------|----------------------------------|
| 阈值 | 300ms（= Android `ViewConfiguration.getDoubleTapTimeout()` 默认值） | — |
| 同项快速两击 | 提交判定 | 通过：判定成立、统计 +1 |
| 同项慢速两击（> 300ms） | 仅选中，不提交 | 通过（400ms 间隔实测：未判定） |
| 跨项快速两击 | 视为改选，不提交（第 1 击落到新项） | 通过：选中态转移到第 2 项 |
| 三击连打 | 第二击已提交，第三击被忽略 | 通过：统计仍为 1（无重复计数） |
| 触发后 | 重置计时器，防止连环提交 | 同上 |
| 提示 | 选中态在判定栏显示 11sp「再次点击该选项可直接提交」 | 通过：选中态提示行出现 |
| 触觉 | 提交瞬间一次轻触反馈（`HapticFeedbackType`，实现层） | 原型以 180ms 轻缩放脉冲代替演示 |
| 基线 | 单击 + 「确认提交」按钮路径不得回归 | 通过 |

**⚠ 实现路径（有坑，务必按此做）**：**不要用 Compose `detectTapGestures(onDoubleTap = ...)`**。
同时注册 `onTap` 与 `onDoubleTap` 时，`onTap` 会被延迟到双击超时（≈300ms）之后才回调——单击选中的手感会明显发粘，正好毁掉两步式“改选很轻快”的优点。

正确做法：**在点击回调里自行比较「同一选项 + 时间戳」**：

```
onOptionClick(i):
    if state == judged: return
    now = clock.now()
    isDouble = (lastIndex == i) && (now - lastTime < 300ms)
    lastIndex = i; lastTime = now
    selected = i
    if isDouble: lastIndex = -1; commit()   // 直接提交
    else: state = picked; render()          // 单击零延迟
```

单击路径不经过任何超时等待，双击由第二击触发提交；`commit()` 与按钮路径共用，因此统计、错题、复习推进、每日打卡只可能有一条执行链。

### 4.5 辅助信息开关（假名 + 规律提示同步）

**裁决（关子 2026-10-15）**：题面假名的显示与隐藏**跟随「显示规律提示」按钮同步切换**——同一个按钮同时控制两项，不再有独立的假名开关。

| 状态 | 按钮文案 | 题面读音行 | 提示面板 |
|------|----------|-----------|----------|
| 关（默认） | 显示规律提示 | 灰色占位「假名」 | 收起 |
| 开 | 隐藏规律提示 | 真实读音（`--reading` 色） | 展开 |
| 已判定 | （按钮隐藏） | **强制显示真实读音** | 收起（规则内容已进抽屉） |

两条派生规则及理由：

1. **判定后强制显示假名**：抽屉里已经给出「读音：よんで」，若题面仍藏着假名，同一信息一显一隐会自相矛盾；判定阶段本就是学习信息完整呈现的时刻。
2. **判定后隐藏按钮**：题面卡压缩需要让位给选项区（§3.1），而展示规律的职责已由抽屉里的解析承接，按钮留着无意义。

按钮语义上从「提示开关」升格为「辅助信息开关」，故文案与图标需同步表达"假名 + 规律"两项含义，不再暗示只管提示。

### 4.6 作答辅助状态的生命周期（无输入模式）

**裁决（关子 2026-10-15）**：**不保留输入模式**——界面只做选择题，不提供输入式切换入口；且任何切换或重置动作都必须清空残留的作答状态。

| 触发动作 | 必须清空的状态 |
|----------|----------------|
| 进入新题（下一题 / 出题） | 选中项 → 未选；辅助开关 → 关；判定态 → 未判定；抽屉 → 收起 |
| 切换筛选（类别/语态/活用/难度） | 同上 + 重建题池（原题丢弃） |
| 切换模块页签（动词 ↔ 形容词） | 各自的选中与判定状态**独立保留**（题目不丢），但不得把动词的选择串到形容词 |
| 切换答题模式（随机练习 ↔ 错题重练） | 同上；进入重练时清空选中与判定 |
| 重置统计 / 清空错题 | 不影响当前题面状态 |
| 进程重启 | 仅持久化错题/统计/打卡；选中项与判定态**不落盘**（重启即回到未作答） |

对应实现：状态类中**不存在** `answerText` 一类输入残留字段，只有 `selectedIndex: Int`（-1 = 未选）；`startQuestion()` 是唯一的题目状态入口，内部统一复位。

### 4.7 键盘与无障碍

| 项 | 规则 |
|----|------|
| 数字键 1–4 | 选择对应选项（judged 后忽略） |
| Enter | picked 态 = 提交；judged 态 = 下一题 |
| Tab | 在选项与抽屉按钮间顺序遍历 |
| contentDescription | 选项读出「第 2 项 読んだ」；判定后补状态「答对」「答错，正确答案是 行って」 |
| 双击与 TalkBack | TalkBack 激活走 `AccessibilityAction` → `onClick` 路径，不产生物理双击时间戳，因此与双击提交逻辑不冲突；读屏用户仍可用判定栏按钮提交 |
| liveRegion | 判定标题区域设 polite，判题即播报 |
| 对比度 | 正文 ≥ 4.5:1；选项文字 `--ink` on `--surface` 实测 12.4:1 |

## 5. 视觉令牌

### 5.1 复用现有令牌（`web/styles.css` :root 与 `Theme.kt` PaperTokens）

| 用途 | 令牌 | 值 |
|------|------|----|
| 页面底 | `--paper` | `#f6f5f0` |
| 卡片 / 抽屉 / 导航 | `--surface` | `#fffefa` |
| 正文 / 主字 | `--ink` | `#26332e` |

**实现过程中踩到的坑（已解决，供后续复用）**：

1. **adb 本地路径**：设了 `MSYS_NO_PATHCONV=1` 后，Windows 版 adb 无法解析 Git Bash 风格路径 `/e/...`，`adb install` 会静默失败（报 `failed to stat`）。本地文件路径必须用 `E:/...` 形式，只有设备侧路径（`/sdcard/...`）需要禁用转换。
2. **签名冲突**：release 与 debug 签名不同，`install -r` 会报 `INSTALL_FAILED_UPDATE_INCOMPATIBLE`，必须先 `uninstall`。
3. **adb 守护进程**：本机 adb server 在多次 Bash 调用之间会被回收，命令内需先 `start-server` 并轮询 `get-state == device` 再动作，否则 tap/install 会丢。
4. **uiautomator 定位优于坐标硬编码**：Compose 的可点区域在父节点上（文本节点 `clickable=false`），按 `content-desc` 或父节点 bounds 定位更稳。
