## 1. 选择题答题界面

### 1.1 判题模型

**单选即判**：点选项 = 选择 + 提交，一次交互。取消输入框、提交按钮、IME 组字守卫（选择题没有输入，日文输入法痛点整体消失）。

| 环节 | 输入式（现状） | 选择题（新） |
|------|----------------|--------------|
| 作答 | 文本输入 + 提交按钮 | 单击选项 |
| 判题时机 | 显式提交 | 点击即判 |
| 判题依据 | `normalizeAnswer` 比对书写/假名/变体 | 选项索引比对（选项本身由引擎生成，无归一化歧义） |
| 键盘 | 依赖日文 IME | 1–4 数字键 / Tab + Enter |

### 1.2 选项生成策略（关键工程点）

> **架构判断：选项生成属于「逻辑」，必须落在引擎层，不得写在 UI。**
> 现状红线是「逻辑在引擎、UI 禁写规则」（docs/current-state.md §6）。选项生成依赖变形结果与错误规则，放 UI 会立刻腐化。

落点：web 端新增 `web/quiz-engine.js`（VM 风格，纯逻辑，配测试）；Android 端新增 `engine/quiz/QuizBuilder.kt`（纯 Kotlin，无 Android 依赖）。两端共用同一份**误形表**数据（JSON，随跨端样例一起校验）。

干扰项按**三类来源**分层，优先级从高到低：

| 优先级 | 来源 | 例（読む・て形） | 教学价值 |
|--------|------|------------------|----------|
| D3 | **经典误形表**（人工维护） | 行いて、食べれる、しれる | 纠错最高 |
| D2 | 同词同形式**其他语态** | 読めて（可能形て形） | 语态辨识 |
| D1 | 同词同语态**其他活用形式**（按相近度排序） | 読んだ（た形） | 形式辨识 |

> **口径修正（2026-10-15 关子确定）**：**四个选项必须全部来自当前目标词的变形形式**，不得混入与当前词无关的其他词汇。
> 因此初版设想中的「D4 同组其他动词的同形式」**已废弃**（曾被用于干扰项，如 来る 的题里出现「掃除します」、思う 的题里出现「切りそう」）。
> 现行实现见 `docs/android-answer-screen-spec.md` §3.2 与 `engine/quiz/QuizBuilder.kt`。

组装规则（硬约束，需测试覆盖）：

1. 四项选项 `normalizeAnswer` 后互不相等，且正确答案位置**随机**；
2. 依次从 D3 → D2 → D1 取（各层轮流取一个，尽量让干扰项来自不同层）；
3. 正确项本身不存在歧义时（如 する 可能形=できる），D2/D1 往往不合格，此时 D3 表是主力；
4. 误形表初版建议 25–30 条，覆盖：行く系例外、ら抜き、する/来る 特例、い形容词错接くない、な形容词（きれい）误判、いい 特例；
5. 选项数固定 4，若可用干扰项不足 3（词库极小时），退化到 3 选项并在测试中允许；
6. **每个选项都必须出现在该词的变形集合内**（该词全部语态 × 全部活用形式 ∪ 该词误形表），由穷举测试机械保证。

测试要求（实现阶段门禁）：
- 每条选项生成用例断言「4 项唯一 + 含正确答案 + 位置分布近似均匀」；
- 误形表每条须有对应断言（证明它确实是**错误**形态：`normalizeAnswer(误形) != normalizeAnswer(正确形)`）；
- 扩展 `web/tools/generate-cross-samples.js` 输出 quiz 组样例，Kotlin 侧同步比对（保持跨端一致性口径）。

### 1.3 三版布局（原型可点）

| 方案 | 布局 | 优势 | 风险 |
|------|------|------|------|
| **A 纸卡竖排** | 选项纵向整宽 + 反馈原位展开 | 点击热区最大，单手拇指可达；信息结构与现状一致，迁移成本最低 | 一屏信息量少，滚动略多 |
| **B 双列网格** | 2×2 网格 + 顶部三格统计 | 密度最高，短选项辨识快；熟练期刷题节奏最好 | 长选项（5 字以上）易换行；误触相邻格 |
| **C 沉浸题卡 + 底部抽屉** | 上半屏纯题面 + 紧凑选项行 + 底部上滑判定抽屉 | 反馈信息可以给得很足（形态/读音/大意/规则）；刷题节奏连贯 | 实现最复杂（抽屉动画 + 高度管理）；题面占比大 |

规格（三版共用）：

| 元素 | 规格 |
|------|------|
| 题面字 | 40sp（A/C 居中 46sp），LXGW 楷体 Bold，字距 +0.02em |
| 选项字 | 17sp（网格/紧凑态 16sp），行高 1.35 |
| 序号 | 26×26 圆角 8px，默认纸底描边，判定后填充绿/红 |
| 选项态 | 默认（纸白 + 1.5px 线）→ 按下（淡绿底）→ 对（绿底绿框 + 勾）→ 错（红底红框 + 叉）→ 正确答案揭晓（绿描边虚线 + 勾） |
| 状态区分 | **颜色 + 图标 + 边框样式三重冗余**，色觉障碍下可判读 |
| 卡片 | 圆角 16px，阴影双层（0 2px 10px / 0 12px 32px，透明度 ≤5%），边框 1px `--line` |
| 进度 | 顶部进度环 46px（本轮完成度）+ 细进度条；方案 C 用圆点序列 |

## 2. 应用图标

### 2.1 三个方向

| 方向 | 风格与元素 | 适用场景 | 文件 |
|------|-----------|----------|------|
| **1 あ・纸页** | 扁平矢量、纸白底 + 墨绿「あ」（楷体感）+ 右上书签角标、细横线暗示纸页 | 贴近现有纸感品牌；桌面浅色壁纸下气质最一致；字形可单独复用为单色主题图标 | `icon-a-ai-paper.svg` |
| **2 る → ます** | 墨绿满底 + 两块纸白字形块（る / ます）+ 变形箭头；极简双色 | **语义唯一性最强**（直接表达“动词变形”这个核心功能），不与通用日语学习 App 雷同；圆形遮罩下最饱满 | `icon-b-henkei.svg` |
| **3 朱印** | 纸底 + 朱红方印描边 + 楷体「あ」，整体旋转 −5° 取手作印章感 | 有文化辨识度与温度；朱红沿用应用「答错」语义色 #A54E45，内外配色同源 | `icon-c-hanko.svg` |

推荐：**方向 2 作为主图标**（功能语义最强、缩到 48dp 仍清晰），方向 1 作为备选（更含蓄、更贴纸感）。方向 3 适合作为「印章式成就/打卡」图形语言引入内页，不一定做主图标。

### 2.2 技术规范（Android 自适应图标）

| 项 | 规范 |
|----|------|
| 画布 | 108×108dp；内容收在中央 **66×66dp 安全区**（三个方向已按此绘制） |
| 分层 | 前景层 = 字形/图形（透明底）；背景层 = 纯色（#326151 / #FFFEFA / #F6F5F0）或极淡纸纹 |
| 输出 | VectorDrawable（`ic_launcher_foreground.xml`）+ 背景色资源；另出 PNG 各密度兜底 |
| 单色主题 | Android 13+ themed icon：取字形轮廓单色版（方向 1 天然满足；方向 2 需简化掉箭头） |
| 商店资产 | 512×512 PNG（Play 若需要）；本次分发方式为本地 APK，商店资产可后补 |
| **落地必做** | 当前 SVG 的字形用**系统字体渲染**，跨设备会漂移；正式接入前把「あ」「る」「ます」转为**轮廓路径**（描边转填充），保证任何环境像素一致 |

### 2.3 遮罩适配（原型内可切换查看）

圆形 / 圆角方 / squircle 三种遮罩下均已预览：方向 2 满底最稳，方向 1、3 依赖中心构图，安全区留白足够、无裁切风险。

## 3. UI 视觉层次提升

### 3.1 现状问题（实测截图结论）

1. **层次扁平**：页面底、卡片、强调区亮度差过小，卡片几乎“浮不起来”，整屏读起来是一片纸色；
2. **状态弱**：判题结果只体现在文字（“答对了/再记一下”），没有颜色块、图标、进度反馈，扫视时抓不到重点；
3. **统计是纯文字**：`答对 0 答错 0 共 0 正确率 —` 一行字排开，既占位又不提供速率感；
4. **缺进度感**：随机练习没有“本轮进行到哪”的坐标，答题像无限流。

### 3.2 改进手段

| # | 手段 | 具体做法 |
|---|------|----------|
| 1 | **三级层次** | 纸底（页面 `#f6f5f0`）→ 纸白卡（`#fffefa` + 1px 线 + 双层轻阴影）→ 强调层（淡绿 `#edf3eb` / 淡橙 `#f8efe6`）；卡片统一圆角 16px |
| 2 | **排版阶梯** | 题面 40–46sp 楷体加粗做视觉锚点；目标表单列 chip（橙系）与题面形成对比；说明文字 12.5–14sp 分三级灰（`--text-strong` / `--reading` / `--meaning`） |
| 3 | **状态双通道** | 判定用「颜色 + 图标」双重编码（绿勾 / 红叉），并用边框样式（实线/虚线）区分“你选的”和“正确答案” |
| 4 | **进度可视化** | 顶部进度环（本轮完成度）+ 细进度条；方案 C 用圆点序列；正确率并入环内数字，替代横排文字 |
| 5 | **统计重构** | 三格小卡（答对 / 答错 / 正确率），数字 17sp 加粗，语义色着色；保留“统计清零”入口但降级为文字按钮 |
| 6 | **动效令牌** | 卡片入场 `translateY(6px)→0 / 220ms`；选项着色 130ms；抽屉上滑 220ms；统一 `cubic-bezier(0.22, 0.61, 0.36, 1)`；**禁弹跳曲线**（P0-3） |
| 7 | **图标统一** | 全项目 Material Icons 填充风格（现状已锁），尺寸 20（按钮）/ 24（导航）；**零 emoji**（P0-1） |

新增令牌（需加进 `Theme.kt` 的 `PaperTokens`，全部取自 web `:root`，不新造色）：
`ReadingText #839087`、`MeaningText #627967`、`BgPaleStrong #E9EEE7`、`LineAccent #C6D4C7`（已有）、阴影两档（`--shadow` 双层）。

## 4. 交互逻辑重设计

### 4.1 答题闭环（新）

```
进入题目
  → 题面（词条 + 目标 chip + 大意 + 提示按钮）
  → 点选选项  ← 唯一必需操作
  → 立即判题：选项着色（绿/红）+ 正确答案揭晓（虚线绿框）
  → 反馈卡/抽屉展开：正确形态 · 读音 · 语态/形式大意 · 变化规则
  → 答错：自动入错题本（沿用现有加权 + 间隔复习机制）
  → 「下一题」
```

### 4.2 反馈节奏（待拍板 Q1）

| 选项 | 行为 | 代价 |
|------|------|------|
| 手动（原型现状） | 判题后停住，点「下一题」 | 需要一次点击；阅读时间可控 |
| 混合 | **答对** 0.8s 自动跳，**答错**必须手动 | 节奏最快，但答对时来不及看规则 |
| 全自动 | 1.2s 自动跳 | 规则说明被跳过，学习价值下降 |

推荐**混合**：答对自动、答错手动（错题必须停下来看规则）。

### 4.3 联动与保留项

| 机制 | 处理 |
|------|------|
| 到期错题优先 / 加权封顶 3 / 会话重试 4 题 / 毕业 6 次 | **原样保留**（引擎与存储层不动） |
| 错题重练横幅 | 保留，样式升级为橙色 chip + 待练计数 |
| 规律提示按钮 | 保留；判题后规则自动进反馈卡，不必再点一次 |
| 每日打卡 / 主页统计 | 不动（`updateDaily` 逻辑不变） |
| 筛选 UI | 从当前两行下拉按钮改为**底部抽屉**（BottomSheet），减少顶部拥挤；选择即重建题池 |
| 键盘与无障碍 | 1–4 选答案、Enter 下一题；选项 Tab 可遍历；`contentDescription` 描述状态（“第 2 项，答对”）；判题结果用 liveRegion 播报 |
| 引导 | 首次进入选择题给一次 1 行说明（“点选项即可作答”），不做教程页 |

### 4.4 状态机（一个模块）

```
idle ──出题──▶ asking ──点选──▶ judged(对) ──下一题──▶ asking | roundEnd
                    │
                    └──点选──▶ judged(错) ──下一题──▶ asking | roundEnd
```

- `judged` 期间选项不可再点，输入锁定；
- `roundEnd`（本轮 N 题走完）：展示小结（本轮对错、正确率环、错题数）+「再来一轮」/「去错题本」；
- 复习模式与随机模式的差异只在出题来源与横幅，状态机一致。

## 5. 待关子拍板（原型确认清单）

| # | 决策点 | 选项 | 我的建议 |
