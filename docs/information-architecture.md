# 信息架构与主要流程

> 状态：Web 学习主页、模块入口和侧栏导航已实现；Android 原生导航仍待原型阶段决定。交互方案参考[导航方案原型](navigation-prototypes.html)。

## 顶层结构

```text
学习主页（每次启动默认进入）
├── 总体学习概览
├── 动词活用模块
├── 形容词活用模块
├── 助词学习模块
├── 更多日语工具入口（随模块逐步加入）
└── 全局错题本（按模块分组）

各学习模块
├── 模块概览／入口
├── 模块提供的功能（例如练习、速查或专用工具）
└── 本模块的详细统计与专属状态
```

模块功能按需提供，不要求对话、文章解析等未来工具强行套用“练习／速查”两个页面。

## 学习主页

- 每次打开应用先显示学习主页，不恢复上次停留在练习题中的页面。
- 同时展示跨模块概览和各模块摘要。
- 首版概览聚焦今日练习量、连续学习天数、哪些模块已有今日活动；模块卡可以显示各自今日题数。
- 不在主页展示详细正确率、每日目标进度或知识点掌握度；这些细节留在模块内部，后续有明确需求再扩充。
- 模块卡是进入模块的主要入口；未来工具可按需增加，不预留一批不可用的空功能。

## 网页导航

- 桌面端采用可折叠侧栏；展开时显示模块名称，折叠时显示“动”“形”“助”等短标记。
- 窄屏端使用默认收起的左侧抽屉，点击菜单按钮覆盖展开；选择页面或点击遮罩后收起。
- 学习主页通过桌面侧栏和窄屏顶部的品牌标记返回；侧栏列出动词、形容词、助词等已启用模块和全局错题本，不重复放置主页按钮。新增模块后按模块接入清单登记。
- 进入模块后由模块呈现自己的功能导航；全局侧栏负责跨模块切换。

## 学习模块页面约定

- 动词、形容词、助词使用同一套模块页签样式，并在当前子页签下展示一致的说明卡。
- 练习控制项共用统一面板与控件尺寸；层级、题型等离散选项使用下拉框，只展示该模块真实有意义的筛选，不为追求数量添加无效控件。
- 每个练习题卡在标题区提供相同的答对、答错、总题数、正确率和独立清零统计；旁侧方法说明使用共享卡片样式。
- 各模块保留独立题库与统计存档；清零某模块统计不会影响错题或每日学习记录。

## 助词学习模块

- 练习是默认入口；综合练习交替出现“根据语境选择助词”和“判断高亮助词在句中的作用”两类题，并保留按题型专项练习。
- 句义判断必须标明目标助词的具体位置，提问当前句中的作用，而不抽象询问“这个助词是什么意思”；选项采用并列、互斥的语义关系描述。
- 作答前先读日文句子和读音；反馈解释目标助词与易混关系，再显示译文，让例句承担主要学习量。
- 学习地图按功能和常见易混点组织专题，作为随时查阅的辅助入口；专题卡仍可直接进入对应练习。
- 入门聚焦核心意义；进阶增加语境对比、焦点和语气辨析。错题按具体题目保存在助词模块内独立复习。

## 错题入口

- 全局错题本是统一入口，错题按模块分组。
- 从全局错题本可进入对应模块复习；模块内也可以提供快捷入口。
- 错题记录和复习框架可以共享，但题目 key、词库、规则和模块状态必须能识别所属模块。
- 非题目型工具是否产生错题由该模块定义；不把所有工具操作都转成错题。

## Android 导航

Android 端遵循原生交互习惯，但具体采用抽屉、底部导航或组合方式尚未决定；在原生页面原型阶段再评估。不要直接把网页侧栏方案当成 Android 的最终导航设计。

Android MVP 以手机竖屏为主，适配不同手机尺寸；平板和横屏不属于首版目标。

## 主要流程

### 首次或重新启动

```text
启动 → 学习主页 → 查看整体／模块摘要 → 选择模块或全局错题本
```

### 模块学习

```text
学习主页 → 选择模块 → 使用模块提供的功能
          → 模块内查看详细统计／本模块错题
          → 返回学习主页或切换全局目的地
```

### 全局错题复习

```text
全局错题本 → 选择模块分组 → 进入对应模块 → 复用该模块的题目与规则重练
```

## 仪表盘数据边界

主页只需要展示便于继续学习的摘要。各模块提供可汇总的只读摘要，不把模块详细数据迁移到主页，也不由主页修改模块复习状态。每日题数和“今日已开始”如何按不同类型工具计量，新增模块时需在模块需求中明确。
