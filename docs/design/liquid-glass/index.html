言の葉 · UI 翻新三方案对照

三个方案共用同一份信息架构、9 个视图、同一套操作路径与状态机，差异只落在视觉外观、布局形态、控件样式与交互反馈。下方三个预览可直接点击操作：切标签、进模块、答题判定、开弹层、换皮肤、切三档材质、注入空态/加载/错误。请任选一个单独打开细看。

决策已闭环（2026-11-08）：关子选定方案 B，并在其基础上追加两条硬要求 —— ① 底部区域改悬浮岛；② 全局统一圆角 24dp，无例外（卡片 / 按钮 / 输入框 / 弹层 / 图片 / 底栏岛同值）。A、C 自此仅作历史对照保留，不再作为候选。B 的落地计划见 docs/android-liquid-glass-plan-b.md。
B 的两处修订（2026-11-08 已落进原型）：底栏由「全宽玻璃条 + 24dp 顶圆角」改为四角同 r 的悬浮岛，原型控制条可切覆盖 / 占位 / 收窄三种浮法；圆角由 28/18/32/14/999 五套值收敛为单值 24，控制条可切 24 / 20 / 16 直观看差异。弹层同步改为四角同 r + 三边离屏 12。

怎么看：设备内容区可滚动 —— 首屏只显示上半部分，向下滚动能看到知识点建议、错题本、书签等完整内容。三方案在同一屏高下可见的信息量不同（C 明显更多），这正是信息密度取舍本身，不是缺页。预览控制条里的「皮肤 / 材质 / 场景 / 状态」是原型工具，不是 App UI；实际 D-041 是完全跟随系统、无手动开关，是否新增材质开关属于待拍板项 Q2。
实测验证：已用本地无头浏览器对三个原型各跑 37 项断言（共 111 项，0 失败）：底栏四标签、模块入口、答题四态、筛选弹层与 Esc、速查搜索换词、解析加载/完成、词详情收藏、空态注入、深浅皮肤与三档材质切换、重置、零 JS 运行时错误；对照页 3 个 iframe 全部渲染。主题令牌差异也经 computed style 实测：卡片圆角 20/24/4px、标题字号 22/26/19px、页边距 18/22/12px、底栏形态「悬浮胶囊 / 悬浮岛 / 平铺线框」、底栏模糊「有 / 有 / 无」。
B 的悬浮岛与统一圆角另跑 34 项断言 0 失败：--radius 与五个别名同解 24px、.card/.btn/.tab/.tabbar 计算圆角均 24px、无 999px 残留、覆盖浮法左右底各 16px（宽 = 屏宽 − 32）、占位浮法 position=relative 且内容不重叠、收窄浮法宽度 280px 水平居中（320/390/496 三档屏宽均不溢出）、弹层四角 24px 且离屏 12px、墨夜与三档材质下岛形与模糊不丢、A/C 两方案未被 B 的岛形污染。

二、设计特点 / 适用场景 / 优缺点 / 取舍

A · 纸感延续

设计特点
保留现有糖果卡／墨夜双皮肤纸卡体系（白卡 + 1dp 细边 + 柔影 / 墨夜零阴影靠细线分层），仅在底栏、弹层、判定抽屉引入玻璃材质。浅色底栏仍是悬浮药丸，深色平铺。
适用场景
渐进上线、低版本用户占比高、回归预算有限、优先保住读屏与可读性基线。
优点
  • 改动面最小，可沿用 Theme.kt / ModuleGeometry / 双皮肤全部资产
  • API 26–30 与 33+ 观感差距最可控
  • 玻璃面数量固定，GPU 开销与崩溃风险最低
  • 纸卡实底，文字对比度与 TalkBack 语义最稳
缺点
  • 视觉新意有限，「全量翻新」感知弱
  • 玻璃只出现在少数位置，材质语言不成体系
  • 与酷安那种整体玻璃观感差距最大
核心取舍
用视觉冲击力换稳定性、低版本一致性与最低回归成本。

B · 全量液态玻璃

设计特点
所有卡片、控件、弹层、底栏统一玻璃语言；背景铺柔和光斑让模糊与折射可见；全局唯一圆角 24dp（卡片 / 按钮 / 输入框 / 弹层 / 图片 / 岛同值）、宽松间距、浮起层级；底栏为四角同 r 的悬浮岛，脱离屏幕三边、玻璃压住身后内容；底栏四枚导航项用线性矢量图标（1.75 描边、无底板、颜色继承文字色）。三档材质切换的效果差异在这一方案里最明显。
适用场景
品牌视觉升级、以中高端机为主的目标用户、愿意承担性能与兼容成本、追求与酷安／iOS 液态玻璃同代质感。
优点
  • 视觉最统一、辨识度最高，翻新感知最强
  • 一套材质语言贯通页面／弹层／控件
  • 三档降级有完整可演示的表达
缺点
  • 玻璃效果依赖 RenderEffect（API 31）与 lens 的 AGSL（API 33）；要让结果与原型一致，minSdk 必须提到 33，等于放弃 Android 8–12（计划 §0.6 / D-051）
  • 同屏多玻璃面 + 滚动 + 弹层叠加的 GPU 开销最大
  • 玻璃上叠玻璃有 RenderThread SIGSEGV 风险（需 exportedBackdrop）
  • 墨夜零阴影细线体系与玻璃高光语言相冲；子集字体在半透明上的对比度待验
  • 统一 24 的几何副作用（实测）：44dp 高按钮与 36dp 小按钮在 r=24 时被形状自身裁到上限（22 / 18），即完全胶囊；卡片与弹层是真正的 24 圆角。要「看起来同一种圆角」需把 r 收到 16，或把按钮加高到 ≥52dp —— 待关子确认（原型控制条可切 24/20/16 直看）
核心取舍
用性能、兼容性与可读性风险换视觉一致性与品牌冲击。

C · 结构化线框

设计特点
不做玻璃：强边界线框、细线栅格背景、4dp 直角、紧凑间距、高密度两列栅格；语态区改为纵向行表；底栏平铺带上边框；胶囊全部改为方形标签。状态一律文字化（「状态 · 」「[ 正确 ]」「提示 · 」），颜色只作辅助通道。
适用场景
长文阅读、TalkBack／无障碍优先、低端机与成本敏感、信息密集型学习、要求全 API 档表现完全一致。
优点
  • 可读性、无障碍与焦点可见性最好
  • 无 backdrop-filter，性能最省、跨 API 表现一致
  • 状态双通道最明确，空态／错误态都给下一步
  • 不受 lens 形状约束与玻璃叠加崩溃影响
缺点
  • 视觉最保守，品牌质感与「翻新」感知最弱
  • 与「液体玻璃」这一诉求本身偏离，本质是第三条路
  • 信息密度高，对小屏与低视力用户可能偏挤
核心取舍
用观感与材质诉求换可用性、性能与全版本一致性。

五、实现与复现

三个原型自包含，可单独双击打开，无构建、无依赖、无网络请求。src/ 下是共享骨架 base.css、三套主题 theme-*.css、共享引擎 engine.js 与模板 shell.html；build.py 把三者内联成三个 HTML。因为引擎与骨架共用，三方案的 IA、页面范围、操作路径、状态机严格一致，差异只由主题层承担。
底栏图标源文件是 src/icons/tab-{home,study,read,mine}.svg（24 viewBox、1.75 描边、stroke="currentColor"），build.py 会把它压成一行注入 engine.js 的 ICONS 占位——必须内联而不是 <img src>，否则深浅皮肤与选中态的颜色继承要维护第二套资源；若构建脚本未跑，ICONS 为空，底栏自动回退文字字形，不会出现空白图标。

决策结果

2026-11-08 已闭环：采用方案 B，并追加两条硬要求：底部改悬浮岛、全局统一圆角（无例外）。原 Q1–Q6 的处置：

  1. 最终采用：B，且不得混入 A / C 的任何形态（含 A 的纸卡、C 的直角线框）。
  2. Q1 三档降级 → 关闭：要让结果与原型一致，产品只保留 glass 一档、minSdk 33，不留 blur / solid 分支（计划 §0.6）。
  3. Q2 材质开关 → 关闭：只有液态玻璃，不提供手动开关；D-041「完全跟随系统深浅色」保留。
  4. Q3 双皮肤 → 已定：两套皮肤同形，只换配色与光源，不降档、不改几何。
  5. Q4 纸感层次 → 废止：旧纸卡三级层次与 ModuleGeometry 双套几何一并作废，改单套 GlassTokens。
  6. Q5 性能不达标 → 关闭：只允许优化实现，不允许改外观降档；阈值见计划 §4.3（T1–T10）。
  7. Q6 验收阈值 → 已定：P95 ≤16.7ms、严重掉帧 ≤1%、同屏玻璃面 ≤8、对比度 ≥4.5:1 等，见计划 §4.3。

仍待确认的唯一一项：统一圆角取 24 时，44dp 按钮与 36dp 小按钮会被形状裁到上限（22 / 18）而呈完全胶囊，与卡片真正的 24 圆角在视觉上不是同一种转角。若要求「看起来同一种圆角」，应改 16（原型控制条可一键切换对比）。
