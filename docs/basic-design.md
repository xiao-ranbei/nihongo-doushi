# 目标系统基本设计

> 状态：基于已确认需求整理。Web 学习主页与模块导航已实现；Android 和后续工具仍属于目标设计。当前代码基线见 [current-state.md](current-state.md)，Android 首版约束见 [android-requirements.md](android-requirements.md)。

## 1. 系统边界

项目是日语学习工具集，初期包含一个网页客户端和一个原生 Android 客户端。两端共享产品概念与共同模块的行为要求，但不是同一套 UI。

当前仓库布局为：

```text
repository/
├── web/                 # 现有静态网页及其测试、资源、开发工具
├── android/             # Kotlin 原生 Android 工程
├── docs/                # 产品、目标设计、当前状态和模块约定
└── README.md            # 仓库入口与运行说明
```

现有网页代码、资源、测试和工具已经整体迁入 `web/`。开始 Android 工程时，在仓库根目录新增 `android/`，不再迁移网页文件。

## 2. 逻辑分层

```text
客户端外壳
├── 学习主页与跨模块导航
├── 模块页面
│   ├── 动词模块：词库、动词规则、练习、速查、模块统计
│   ├── 形容词模块：词库、形容词规则、练习、速查、模块统计
│   └── 未来日语工具：按需求选择练习、语音、文章分析等交互
└── 共享学习服务
    ├── 按模块分组的全局错题本与复习调度
    ├── 全局连续学习记录
    ├── 今日活动摘要
    └── 统一视觉与无障碍约定
```

模块拥有自己的领域数据、规则、筛选、页面和详细统计。共享服务只负责跨模块能力，不接管领域规则。主页读取模块摘要，不直接改变模块状态。

## 3. Web 与 Android

### Web

- 保持静态、离线优先的网页形态，使用 HTML、CSS 与 JavaScript。
- 页面采用共享应用外壳、学习主页、桌面可折叠侧栏和窄屏抽屉；模块功能由各模块内部呈现。
- `web/verb-engine.js` 与 `web/adjective-engine.js` 分别提供网页端规则引擎；主页摘要数据存放在版本化的本地每日记录中。

### Android

- 使用 Kotlin 实现原生界面和动词／形容词规则引擎，不以 WebView 作为正式客户端 UI。
- 保留网页现有 JavaScript 引擎；当前两模块在两端对齐，并通过共用测试样例校验规则结果一致。
- 共享样例应覆盖主要规则、特殊动词／形容词、答案变体和归一化行为；新增规则先更新样例，再分别验证 Kotlin 与 JavaScript 实现。
- Android 的具体 UI 工具包、最低 Android 版本和全局导航样式留待原生原型与工程搭建阶段确定。

## 4. 模块边界与接入

当前不建设插件注册表。新增模块由代码显式接入导航、主页摘要和共享服务，先保持实现简单。模块之间只共享稳定的基础能力，不共享彼此的领域状态。

每个模块按需定义：

- 标识、名称、短标记、介绍和支持的平台。
- 词库／输入数据、规则引擎及纯逻辑测试。
- 可选能力：练习、速查、统计、对话、文章处理等。
- 模块独立筛选、详细统计、持久化数据和页面状态。
- 可提供给主页的最小摘要，例如今日活动量和今日是否开始。
- 是否接入共享错题框架；只有能明确生成可复习题目的模块才适用。
- 什么用户行为算一次有效学习活动并计入全局连续学习记录。

新增模块按 [module-guide.md](module-guide.md) 手工接入；当多个模块形成稳定重复模式后，再单独评估是否需要注册框架。

## 5. 数据和持久化

### 共享与独立数据

| 数据 | 归属 |
| --- | --- |
| 题库、规则、答案、筛选条件 | 各模块 |
| 正误统计、详细学习状态 | 各模块 |
| 今日模块摘要 | 模块维护原始活动，主页仅读取汇总 |
| 错题记录和复习调度 | 共享框架，记录必须包含模块标识和稳定题目 key |
| 全局连续学习记录 | 共享学习服务；每个模块需定义有效活动边界 |
| 网络服务数据 | 将来按联网模块分别授权、说明和处理，不默认共享上传 |

Web 和 Android 的本地记录首版相互独立，不做账号、云同步、自动迁移或备份。Android 数据保存在应用本机；卸载或设备损坏可能造成丢失。

### 今日摘要

主页需要显示总今日练习量与各模块今日活动。当前网页仅有累计答题统计和连续学习记录，没有可按日拆分的模块活动计数；实现主页前需要新增本地日活动数据，并明确统计时区、日期切换和模块 activity 计量方式。

### 存储要求

- 本地持久化需可校验、可处理缺失或损坏数据，并向用户明确报告存储失败。
- 持久化结构需带版本或迁移约定；改变数据语义时提供迁移或明确重置路径。
- 模块数据 key 必须含模块边界，避免不同模块的题目 ID 冲突。
- Android 存储技术选择（例如关系型库或轻量偏好存储）在数据结构确定后再决定，不预先绑定特定实现。

## 6. 离线、联网和隐私

- 首版 Web 核心功能与 Android MVP 完全离线可用。
- 未来模块可按需联网，但必须逐模块声明联网原因、访问的数据、权限、失败提示和离线退化行为。
- 需要麦克风或其他系统权限的工具仅在对应功能启用时申请，并说明用途；Android MVP 当前不要求通知、语音、桌面组件或后台任务。
- 不在客户端提交服务器密钥，不默认把文章、语音或学习记录上传；未来服务端处理须另行确认数据流和隐私要求。

## 7. 质量约束

- 共享品牌氛围和纸感配色；Web 继续使用 CSS 语义令牌，Android 使用对应主题资源。
- Web 与 Android 对当前共同模块保持行为一致，并用共同样例测试引擎输出。
- 各端分别遵循平台的键盘、输入法、返回、焦点和无障碍语义。
- 保持离线状态下的明确反馈；存储、网络和权限错误不能伪装成成功。
- 共享错题服务与模块规则解耦；模块可选择是否参与错题复习。

## 8. 实施顺序与未决项

1. Web 已具备学习主页、跨模块摘要、模块导航和全局错题入口。
2. 开始 Android 时，在同一仓库新增 `android/` Kotlin 工程。
3. 完成 Android 手机竖屏原生原型，再确定应用内导航与具体控件方案。
4. 建立 Web／Kotlin 共用规则测试样例，实施 MVP：主页、动词与形容词练习、全局错题复习。
5. 速查、导入／导出、联网工具、数据备份和新模块依需求逐步加入。

最低 Android 版本、Kotlin UI 框架、Android 存储方案、包名和正式发布计划仍待工程搭建阶段确认。
