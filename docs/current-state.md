# 当前实现背景

> 更新时间：2026-10-17
> 本文记录当前实现，以网页端为主线；Android 原生客户端已实现底部四标签框架（主页/学习/阅读/我的，D-024）+ 动词／形容词三层练习 + 助词模块 + 错题本，详见 [android-four-tab-spec.md](android-four-tab-spec.md) 与 [android-two-tab-spec.md](android-two-tab-spec.md)、[android-answer-screen-spec.md](android-answer-screen-spec.md)。

## 1. 项目概述

当前网页端位于 `web/`，是一个纯静态、离线可用的日语学习工具，提供学习主页、动词活用、形容词接续、助词学习、速查、错题复习和文章阅读（AI 解析）。用户用浏览器打开 `web/index.html` 即可使用；除文章阅读的 AI 解析需用户自备模型服务（D-045）外，运行时不需要服务器、构建工具或第三方题库。

界面、规则引擎和记录均在浏览器本地运行。答题统计、每日练习记录和错题保存在当前浏览器的 `localStorage` 中，不提供云端同步。

每次打开网页默认进入学习主页。桌面端侧栏与主内容区分别滚动，页面外层锁定动态视口且不参与滚动；答题后焦点滚动主内容区时，侧栏保持固定。**大屏等比放大（zoom）必须同步补偿高度**：1600×900 起 zoom 1.15、2200×1150 起 1.3、3000×1500 起 1.45，壳层与两个滚动容器的高度写成 `calc(100dvh / 比例)`——zoom 会把 `height: 100dvh` 一起放大，而 `html/body` 是 `overflow: clip`，不补偿会让底部内容直接被裁（2026-11-10 修，1920×1080 实测底部 162px 滚不到）。桌面侧栏左上角的“日”品牌可返回主页，侧栏不重复放置主页按钮，折叠状态在主页导航时保留。窄屏使用左侧抽屉，顶部“日”品牌可返回主页，顶部栏固定，主页内容在独立滚动区内浏览，底部内容带安全留白。动词、形容词和助词是独立学习模块；动词与形容词错题在全局错题本中分组，助词错题在助词模块内复习。文章阅读是第四个模块（B0–B9，见 [web-read-analyzer-plan.md](web-read-analyzer-plan.md)）：贴文本地切段、点段解析逐词/译文、点词详情、结构化语法、朗读、图片 OCR、AI 助手与本地埋点，解析题可经 `resolveEngineRef` 反查进既有练习。Android 端为同一套模块的原生实现（动词、形容词、助词与共享错题本 + AI 文章解析），导航为底部四标签（主页/学习/阅读/我的）；整套 UI 已按**方案 B 液态玻璃**重做（悬浮岛底栏、全局单值 24dp 圆角、玻璃采样 `vibrancy → blur → lens`，见 [android-liquid-glass-plan-b.md](android-liquid-glass-plan-b.md)）。「排版」「撰写」与「查词」仍是规划中占位。

## 2. 总体结构

```text
web/index.html ── 页面结构与交互节点
    │
    ├── web/styles.css ── 主题、布局、响应式与动效
    ├── web/font/fonts.js ── 本地字体资源清单
    └── web/app.js ── 页面状态、事件、渲染、题目调度与存储
           ├── web/verb-engine.js ── 动词数据、活用、答案归一化与说明
           ├── web/adjective-engine.js ── 形容词数据、变形与说明
           ├── web/particle-engine.js ── 助词专题、对比题与分层讲解
           ├── web/read-engine.js ── 文章阅读纯逻辑（切段/解析重建/反查/罗马音）
           ├── web/read-client.js ── 网络层（transport 注入、四次调用、错误映射）
           ├── web/read-prompts.js ── 四条系统提示词（自写，D-036）
           ├── web/read-view.js ── 阅读视图渲染（逐词/抽屉/状态）
           ├── web/read-tts.js / read-ocr.js / read-stats.js ── 朗读 / 图片 OCR 压缩 / 本地埋点
           └── 浏览器 localStorage ── 错题、统计与连续练习记录 + 阅读五键
```

页面通过普通 `<script defer>` 加载，顺序为字体清单、动词引擎、形容词引擎、助词引擎、应用脚本。三个引擎以 UMD 方式导出：浏览器中挂到 `window`，Node.js 测试中通过 `module.exports` 使用。

| 模块 | 主要职责 | 设计边界 |
| --- | --- | --- |
| `web/index.html` | 学习主页、导航、模块视图、表单与无障碍语义 | 不包含活用算法 |
| `web/app.js` | DOM 引用、页面状态、事件、题目选择、反馈、统计和本地存储 | 调用引擎，不维护独立的日语变形规则 |

## 3. 功能与页面

学习主页提供今日答题量、连续学习天数、已开始模块数量和各模块今日题数，可从侧栏或窄屏顶部的“日”品牌返回。侧栏在动词、形容词、助词、敬语、文章阅读和全局错题本之间切换；动词模块内提供「练习／活用速查／敬语」三个子页（敬语在侧栏另有独立入口，复用同一视图，切回「动词活用」时落回练习），形容词模块内提供「练习／速查」，助词模块默认进入「练习」，并提供「学习地图／错题复习」辅助入口；文章阅读提供「输入／阅读器／模型设置」三态。

### 3.1 动词练习

- 词库覆盖五段、一段和不规则动词，共 **173** 词（五段 98／一段 51／不规则 24，2026-11-10 由 79 分两批扩容：先按音便词尾与自他配对补 45 词，再按语体补 47 个书面语与复合动词，见 [web-honorific-module-spec.md](web-honorific-module-spec.md) §2）；练习目标由语态与活用形式组合构成。
- 可按动词类别、变形类型、活用形式和基础／进阶难度筛选。选择具体活用形式时，难度筛选停用，避免筛选条件冲突。
- 题池按筛选条件建立并洗牌；一轮内避免重复同一题，并尽量避开最近出现过的动词。到期错题优先于普通随机题。
- 题面默认隐藏读音和类别，用户可展开查看；可在判题前查看规律提示。
- 判题后展示正误、正确形态、读音、表达大意和变化规则，并更新本模块统计。
- 答对／答错、总题数和正确率作为紧凑统计区并入随机练习标题区；不再单独显示“练习统计”标题或选中框，窄屏时统计区排在标题下方。
- 答题正确／错误时的绿色／红色扫光覆盖整张练习卡，而不是单独扫过统计区。

### 3.2 动词活用速查

用户可搜索并选择动词及变形类型，查看分组的完整活用表、表达大意和变化规则。每个形式都可直接转成对应练习题，从查阅进入练习。

### 3.3 敬语

动词模块的第三个子页，侧栏同时提供独立入口（复用 `verb` 视图，不新增顶层视图）。2026-11-10 实现，设计与取舍见 [web-honorific-module-spec.md](web-honorific-module-spec.md)。

- 三层对照表：按所选动词列出尊敬語／謙譲語／丁寧語的ます形、构成规则与使用场合；特殊说法标「特殊」，不可用层给「—」并说明原因（如自然现象动词）。
- 练习：把普通形换成指定类别的敬语（ます形），判题接受汉字、假名与罗马字；答错反馈会说明规则或「特殊说法需整词记忆」，错题进入本轮重练队列，答对／答错计入 `honorificAnswers`。
- 敬语诊断：按「动作主体」（我／己方、对方、第三方）与「听话人是否公司外部」给出该用哪一类，并说明理由（含内外关系规则）。
- 二重敬语检查：词表匹配 10 类常见叠加（おっしゃられる、ご覧になられる、拝見させていただく 等），给出纠正与原因；`severity` 区分错误与冗余。
- 场景例句：6 个场景各 4 句手写例句，标注「谁对谁」，可筛选并直接练句中的动词；不联网、不调用模型。
- 首版未做：可配置面板（8 项设置均按默认值运行）、场景判断选择题、接入全局错题本。

### 3.4 形容词练习与速查

- 练习覆盖い形容词、な形容词及常见形式，包括名词修饰、现在／过去肯定与否定、て形和状语形式。
- 按类别、形式和难度筛选；题目、统计和错题状态与动词练习分别管理。
- 形容词统计卡位于本模块练习卡标题区，保持与动词练习一致的布局。
- 速查页展示两类形容词的接续对照与常见特例，每种形式可直接进入练习。
- 形容词引擎提供书写形式、假名形式及可接受变体；「いい」等特殊变化由规则引擎显式处理。

### 3.5 助词学习

- 助词专题按功能和易混点组织，覆盖は／が、に／で、に／へ、を、の、と／や、も、から／まで、だけ／しか。
- 练习是模块主入口；默认综合练习严格交替两种题型：根据语境选择助词，以及在完整句子中判断高亮助词的作用。层级和题型使用下拉框选择，也可分别切换为单一题型专项练习。
- 句义判断题用四个同类选项考查助词在当前句子中的语义关系；作答前不显示中文译文，反馈说明目标助词的作用、易混点并揭示译文。
- 同一专题提供入门解释与进阶说明；练习题带上下文，填空题允许题目明确标记的多个自然答案。
- 学习地图作为辅助入口，提供专题例句与入门／进阶说明；从专题仍可直接进入该组练习。
- 助词错题、答对／答错统计和每日练习量分别保存；清零助词答题统计不会删除错题或每日记录。

### 3.6 错题与复习

错题视图按动词／形容词分组，可分别启动重练；重练时练习页显示常驻状态横幅。错题支持 JSON 导入、导出和清空，清空前要求确认。练习统计可单独清零，不会删除错题。

## 4. 关键业务流程

### 4.1 启动与出题

1. 应用初始化时读取错题、统计和每日练习记录，填充筛选及速查控件。
2. 根据当前筛选生成目标题池；优先挑选符合筛选条件且已到期的错题，否则从洗牌后的普通题池取题。
3. 将目标词条、目标形式、引擎计算出的结果和稳定题目 key 组成当前题目，再渲染题面。
4. 速查表的「练这题」入口直接构造指定目标题，不改变题目的生成规则。

### 4.2 答题与反馈

1. 提交答案时先检查输入法是否仍处于组字状态；组字中的回车不提交。
2. 对输入做归一化后与正确书写、假名及引擎提供的变体比较。
3. 判定后锁定输入框和提交按钮，展示反馈并更新正误统计；记录当日练习，并将焦点移到「下一题」。
4. 答错时创建或更新错题；答对时推进该错题的复习进度，达到毕业条件后从错题集移除。

### 4.3 间隔复习

- 错题答错后，复习进度重置；本次会话中再完成 4 道题后可重新出现，跨会话则按计划日期到期。
- 连续答对的复习间隔依次为 1、3、7、14、30 天；连续 6 次正确复习后从错题集中移除。
- 到期题会按错题次数加权抽取，但权重有上限，避免单道错题长期占用题目。
- 动词和形容词共用错题存储与复习进度字段，但使用不同题目 key 和独立的筛选、重练入口。

## 5. 领域数据与本地存储

### 5.1 引擎输入与输出

- 动词题由 `verbId`、`voiceId`、`inflectionId` 标识。引擎先派生语态，再执行具体活用，结果包含书写形式和假名形式。
- 形容词题由 `adjectiveId`、`formId` 标识。引擎返回主要形式及可接受变体。
- 助词题由 `questionId`、`lessonId`、学习层级和题型标识；句义判断题还明确标记目标助词及其所在位置。
- 两个引擎同时提供规则说明，反馈和速查视图直接呈现说明文本；变形规则不放在 UI 层。
- 答案归一化集中在动词引擎，供两个模块共用，可处理汉字／假名／常见罗马字输入及常见宽窄、大小写和假名差异。

### 5.2 存储键

| `localStorage` 键 | 内容 |
| --- | --- |
| `japanese-verb-practice-mistakes-v1` | 动词与形容词错题及其复习进度 |
| `japanese-particle-practice-mistakes-v1` | 助词模块错题题目 ID |
| `japanese-particle-practice-stats-v1` | 助词答对、答错计数 |
| `japanese-verb-practice-stats-v1` | 动词答对、答错计数 |
| `japanese-verb-practice-adj-stats-v1` | 形容词答对、答错计数 |
| `japanese-verb-practice-daily-v1` | 最近练习日期、当前连续天数、最佳连续天数，以及动词／形容词／助词／敬语当日答题数 |
| `japanese-read-analyzer-config-v1` | 文章阅读模型配置（地址/模型/密钥/温度/视觉模型/助手开关，D-045） |
| `japanese-read-analyzer-cache-v1` | 按段解析缓存（词/译文/词详情/语法，500 条上限，D-046） |
| `japanese-read-analyzer-budget-v1` | 每日 100 / 每篇 20 次请求预算计数（D-047） |
| `japanese-read-analyzer-stats-v1` | 本地埋点：解析次数/缓存命中/耗时/7 组错误归并（不出网，D-037/D-047） |
| `japanese-read-analyzer-activity-v1` | 今日阅读段数与收藏词数（D-048；书签复用 `japanese-verb-practice-bookmarks-v1`） |

错题记录按模块保存对应词条 ID 和目标形式，并包含错误次数、最近错误答案、更新时间、连续正确次数、复习间隔和下次到期时间。旧版没有 `module` 字段的记录按动词错题兼容。会话内重试计数用于当前会话调度，不包含在导出文件中。

读取到无法解析或结构不合法的数据时，会显示提示并以空记录继续；浏览器拒绝本地存储时，数据仅在当前页面内存中保留，并通过提示告知用户。导入的 JSON 会经过结构校验，重复题目按题目 key 合并。

## 6. 质量属性与维护约定

- **离线与隐私：** 运行时资源随项目提供，不依赖外部服务；学习记录保存在当前浏览器。
- **可访问性：** 使用语义化表单和视图；反馈、提示及状态使用适当的 `aria-live`／状态属性，支持键盘操作与输入法组字。
- **响应式与动效：** 练习双栏布局在较窄屏幕堆叠；焦点状态清晰，并尊重减少动态效果的系统设置。
- **样式一致性：** 动词、形容词和助词模块共用页签、说明卡、练习控制面板与答题统计布局；颜色通过 `web/styles.css` 的语义令牌维护，`web/tests/styles.test.js` 检查组件契约。Android 端同理：配色收在 `ui/theme/Theme.kt` 的 `Palette` 表里，几何与材质收在 `ui/theme/GlassTokens.kt`（唯一圆角 24dp、模糊 16dp、折射 18/24dp、三档投影、岛几何、三团光斑），页面只经 `MaterialTheme.colorScheme`／`paperColors()`／`glassColors()`／`moduleTone()`／`posBackgroundColor()` 取色取形，**不写硬编码色值、不写字面量圆角**（`GlassContractTest` 静态守卫）；玻璃面一律走 `GlassSurface` / `Modifier.glassPanel`，弹层走 `GlassBottomSheet` / `GlassAlertDialog`。主题跟随系统深浅色自动切换两套皮肤，见 [android-theme-spec.md](android-theme-spec.md)。
- **字体完整性：** `web/font/fonts.js` 声明运行时字体；新增词条或界面文字后，按网页端说明重建字体子集，并运行字体契约测试。
- **测试：** 引擎测试覆盖变形和答案处理；UI 冒烟测试验证页面接线与主要闭环；字体、样式测试守护静态资源契约。运行完整测试：

