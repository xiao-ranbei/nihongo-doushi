# 当前实现背景

> 更新时间：2026-10-17
> 本文记录当前实现，以网页端为主线；Android 原生客户端已实现底部四标签框架（主页/学习/阅读/我的，D-024）+ 动词／形容词三层练习 + 助词模块 + 错题本，详见 [android-four-tab-spec.md](android-four-tab-spec.md) 与 [android-two-tab-spec.md](android-two-tab-spec.md)、[android-answer-screen-spec.md](android-answer-screen-spec.md)。

## 1. 项目概述

当前网页端位于 `web/`，是一个纯静态、离线可用的日语学习工具，提供学习主页、动词活用、形容词接续、助词学习、速查和错题复习。用户用浏览器打开 `web/index.html` 即可使用；运行时不需要服务器、构建工具、外部 API 或第三方题库。

界面、规则引擎和记录均在浏览器本地运行。答题统计、每日练习记录和错题保存在当前浏览器的 `localStorage` 中，不提供云端同步。

每次打开网页默认进入学习主页。桌面端侧栏与主内容区分别滚动，页面外层锁定动态视口且不参与滚动；答题后焦点滚动主内容区时，侧栏保持固定。桌面侧栏左上角的“日”品牌可返回主页，侧栏不重复放置主页按钮，折叠状态在主页导航时保留。窄屏使用左侧抽屉，顶部“日”品牌可返回主页，顶部栏固定，主页内容在独立滚动区内浏览，底部内容带安全留白。动词、形容词和助词是独立学习模块；动词与形容词错题在全局错题本中分组，助词错题在助词模块内复习。Android 端为同一套模块的原生实现（动词、形容词、助词与共享错题本），导航为底部四标签（主页/学习/阅读/我的）。「阅读」标签与「查词」「模型/API 设置」等预留位是规划中占位，无真实能力。

## 2. 总体结构

```text
web/index.html ── 页面结构与交互节点
    │
    ├── web/styles.css ── 主题、布局、响应式与动效
    ├── web/font/fonts.js ── 本地字体资源清单
    └── web/app.js ── 页面状态、事件、渲染、题目调度与存储
           ├── web/verb-engine.js ── 动词数据、活用、答案归一化与说明
           ├── web/adjective-engine.js ── 形容词数据、变形与说明
           ├── web/particle-engine.js ── 助词专题、对比题与分层讲解
           └── 浏览器 localStorage ── 错题、统计与连续练习记录
```

页面通过普通 `<script defer>` 加载，顺序为字体清单、动词引擎、形容词引擎、助词引擎、应用脚本。三个引擎以 UMD 方式导出：浏览器中挂到 `window`，Node.js 测试中通过 `module.exports` 使用。

| 模块 | 主要职责 | 设计边界 |
| --- | --- | --- |
| `web/index.html` | 学习主页、导航、模块视图、表单与无障碍语义 | 不包含活用算法 |
| `web/app.js` | DOM 引用、页面状态、事件、题目选择、反馈、统计和本地存储 | 调用引擎，不维护独立的日语变形规则 |
| `web/verb-engine.js` | 动词词库、语态与活用、规则解释、输入归一化及罗马字转假名 | 纯逻辑，不访问 DOM 或浏览器存储 |
| `web/adjective-engine.js` | 形容词词库、形式转换、可接受变体和规则解释 | 纯逻辑；答案归一化复用动词引擎 |
| `web/particle-engine.js` | 助词专题、语境例句、入门／进阶讲解、填空与句义判断题 | 纯数据与判题，不访问 DOM 或浏览器存储 |
| `web/styles.css` | 纸感主题、组件样式、响应式布局和动画 | 颜色通过 CSS 语义令牌管理 |
| `web/font/`、`web/icon/` | 本地字体资源与 favicon | 字体子集生成脚本仅用于开发维护 |
| `web/tests/`、`web/tools/` | 引擎、UI 接线、样式和字体测试及可选开发工具 | UI 冒烟测试使用零依赖 DOM 桩 |

## 3. 功能与页面

学习主页提供今日答题量、连续学习天数、已开始模块数量和各模块今日题数，可从侧栏或窄屏顶部的“日”品牌返回。侧栏在动词、形容词、助词和全局错题本之间切换；动词模块内提供「练习／活用速查」，形容词模块内提供「练习／速查」，助词模块默认进入「练习」，并提供「学习地图／错题复习」辅助入口。

### 3.1 动词练习

- 词库覆盖五段、一段和不规则动词；练习目标由语态与活用形式组合构成。
- 可按动词类别、变形类型、活用形式和基础／进阶难度筛选。选择具体活用形式时，难度筛选停用，避免筛选条件冲突。
- 题池按筛选条件建立并洗牌；一轮内避免重复同一题，并尽量避开最近出现过的动词。到期错题优先于普通随机题。
- 题面默认隐藏读音和类别，用户可展开查看；可在判题前查看规律提示。
- 判题后展示正误、正确形态、读音、表达大意和变化规则，并更新本模块统计。
- 答对／答错、总题数和正确率作为紧凑统计区并入随机练习标题区；不再单独显示“练习统计”标题或选中框，窄屏时统计区排在标题下方。
- 答题正确／错误时的绿色／红色扫光覆盖整张练习卡，而不是单独扫过统计区。

### 3.2 动词活用速查

用户可搜索并选择动词及变形类型，查看分组的完整活用表、表达大意和变化规则。每个形式都可直接转成对应练习题，从查阅进入练习。

### 3.3 形容词练习与速查

- 练习覆盖い形容词、な形容词及常见形式，包括名词修饰、现在／过去肯定与否定、て形和状语形式。
- 按类别、形式和难度筛选；题目、统计和错题状态与动词练习分别管理。
- 形容词统计卡位于本模块练习卡标题区，保持与动词练习一致的布局。
- 速查页展示两类形容词的接续对照与常见特例，每种形式可直接进入练习。
- 形容词引擎提供书写形式、假名形式及可接受变体；「いい」等特殊变化由规则引擎显式处理。

### 3.4 助词学习

- 助词专题按功能和易混点组织，覆盖は／が、に／で、に／へ、を、の、と／や、も、から／まで、だけ／しか。
- 练习是模块主入口；默认综合练习严格交替两种题型：根据语境选择助词，以及在完整句子中判断高亮助词的作用。层级和题型使用下拉框选择，也可分别切换为单一题型专项练习。
- 句义判断题用四个同类选项考查助词在当前句子中的语义关系；作答前不显示中文译文，反馈说明目标助词的作用、易混点并揭示译文。
- 同一专题提供入门解释与进阶说明；练习题带上下文，填空题允许题目明确标记的多个自然答案。
- 学习地图作为辅助入口，提供专题例句与入门／进阶说明；从专题仍可直接进入该组练习。
- 助词错题、答对／答错统计和每日练习量分别保存；清零助词答题统计不会删除错题或每日记录。

### 3.5 错题与复习

错题视图按动词／形容词分组，可分别启动重练；重练时练习页显示常驻状态横幅。错题支持 JSON 导入、导出和清空，清空前要求确认。练习统计可单独清零，不会删除错题。

## 4. 关键业务流程

### 4.1 启动与出题

1. 应用初始化时读取错题、统计和每日练习记录，填充筛选及速查控件。
2. 根据当前筛选生成目标题池；优先挑选符合筛选条件且已到期的错题，否则从洗牌后的普通题池取题。
3. 将目标词条、目标形式、引擎计算出的结果和稳定题目 key 组成当前题目，再渲染题面。
4. 速查表的「练这题」入口直接构造指定目标题，不改变题目的生成规则。

### 4.2 答题与反馈

1. 提交答案时先检查输入法是否仍处于组字状态；组字中的回车不提交。
2. 对输入做归一化后与正确书写、假名及引擎提供的变体比较。
3. 判定后锁定输入框和提交按钮，展示反馈并更新正误统计；记录当日练习，并将焦点移到「下一题」。
4. 答错时创建或更新错题；答对时推进该错题的复习进度，达到毕业条件后从错题集移除。

### 4.3 间隔复习

- 错题答错后，复习进度重置；本次会话中再完成 4 道题后可重新出现，跨会话则按计划日期到期。
- 连续答对的复习间隔依次为 1、3、7、14、30 天；连续 6 次正确复习后从错题集中移除。
- 到期题会按错题次数加权抽取，但权重有上限，避免单道错题长期占用题目。
- 动词和形容词共用错题存储与复习进度字段，但使用不同题目 key 和独立的筛选、重练入口。

## 5. 领域数据与本地存储

### 5.1 引擎输入与输出

- 动词题由 `verbId`、`voiceId`、`inflectionId` 标识。引擎先派生语态，再执行具体活用，结果包含书写形式和假名形式。
- 形容词题由 `adjectiveId`、`formId` 标识。引擎返回主要形式及可接受变体。
- 助词题由 `questionId`、`lessonId`、学习层级和题型标识；句义判断题还明确标记目标助词及其所在位置。
- 两个引擎同时提供规则说明，反馈和速查视图直接呈现说明文本；变形规则不放在 UI 层。
- 答案归一化集中在动词引擎，供两个模块共用，可处理汉字／假名／常见罗马字输入及常见宽窄、大小写和假名差异。

### 5.2 存储键

| `localStorage` 键 | 内容 |
| --- | --- |
| `japanese-verb-practice-mistakes-v1` | 动词与形容词错题及其复习进度 |
| `japanese-particle-practice-mistakes-v1` | 助词模块错题题目 ID |
| `japanese-particle-practice-stats-v1` | 助词答对、答错计数 |
| `japanese-verb-practice-stats-v1` | 动词答对、答错计数 |
| `japanese-verb-practice-adj-stats-v1` | 形容词答对、答错计数 |
| `japanese-verb-practice-daily-v1` | 最近练习日期、当前连续天数、最佳连续天数，以及动词／形容词／助词当日答题数 |

错题记录按模块保存对应词条 ID 和目标形式，并包含错误次数、最近错误答案、更新时间、连续正确次数、复习间隔和下次到期时间。旧版没有 `module` 字段的记录按动词错题兼容。会话内重试计数用于当前会话调度，不包含在导出文件中。

读取到无法解析或结构不合法的数据时，会显示提示并以空记录继续；浏览器拒绝本地存储时，数据仅在当前页面内存中保留，并通过提示告知用户。导入的 JSON 会经过结构校验，重复题目按题目 key 合并。

## 6. 质量属性与维护约定

- **离线与隐私：** 运行时资源随项目提供，不依赖外部服务；学习记录保存在当前浏览器。
- **可访问性：** 使用语义化表单和视图；反馈、提示及状态使用适当的 `aria-live`／状态属性，支持键盘操作与输入法组字。
- **响应式与动效：** 练习双栏布局在较窄屏幕堆叠；焦点状态清晰，并尊重减少动态效果的系统设置。
- **样式一致性：** 动词、形容词和助词模块共用页签、说明卡、练习控制面板与答题统计布局；颜色通过 `web/styles.css` 的语义令牌维护，`web/tests/styles.test.js` 检查组件契约。
- **字体完整性：** `web/font/fonts.js` 声明运行时字体；新增词条或界面文字后，按网页端说明重建字体子集，并运行字体契约测试。
- **测试：** 引擎测试覆盖变形和答案处理；UI 冒烟测试验证页面接线与主要闭环；字体、样式测试守护静态资源契约。运行完整测试：

  ```text
  node --test tests/verb-engine.test.js tests/adjective-engine.test.js tests/particle-engine.test.js tests/styles.test.js tests/font.test.js tests/ui.test.js
  ```

当前基线（2026-10-18 实测）：网页端 6 个测试文件共 121 项全绿；Android 端 `./gradlew :app:testDebugUnitTest` 111 项全绿，仪器化 `TalkBackMergeTest` 4 项全绿（qa36 模拟器，读屏语义树口径，见 D-030/D-031）。

未解决的遗留问题（预留位转正清单、跨端数据缺口、技术债务等）统一登记在 [known-issues.md](known-issues.md)，不要在本文件重复罗列。

在 `web/` 目录运行测试。维护和扩展时应保持「规则在引擎、交互与编排在 `web/app.js`、结构在 HTML、表现与主题在 CSS」的边界。新增规则应补引擎测试；新增页面节点或交互应补 UI 测试；新增界面文字或日语词条应同步更新 `web/font/` 字体子集。
