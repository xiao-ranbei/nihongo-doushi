# 新增日语模块指南

本项目当前使用显式集成，不使用插件注册框架。新增工具时，先定义模块边界，再按清单接入主页、导航和共享服务；不要为了预想中的模块数量提前抽象通用运行时。

## 模块原则

1. 模块拥有自己的领域数据、规则、输入校验、筛选、页面和详细统计。
2. 模块可以选择练习、速查、语音对话、文章解析等适合自身的能力，不要求共用固定页面模板。
3. 模块可选接入共享错题复习；只有存在稳定、可复现且可判定的题目时才加入错题本。
4. 共享服务通过明确的模块 ID 和题目 key 工作，不依赖动词模块字段。
5. Web 与 Android 当前共同模块要对齐规则；未来新模块是否双端支持逐项决定。
6. 新模块先手工接入。多个模块形成稳定共性后，再提交独立的抽象提案。

## 接入清单

### 产品与交互

- 写明模块名称、目标学习问题、目标用户操作和明确不做的内容。
- 决定该模块支持 Web、Android 或两端，以及两端首版范围是否相同。
- 明确模块进入入口、返回路径、空状态、错误状态和学习完成反馈。
- 定义哪些操作算一次有效学习活动并计入全局连续学习记录。
- 定义可提供给主页的最小摘要，不把详细模块统计复制到全局主页。

### 数据与规则

- 为模块分配稳定的模块 ID；词条和题目 key 带模块边界，确保不与其他模块冲突。
- 纯领域规则放在模块引擎，不写入 DOM、视图或 Android 页面代码。
- Android 新增对应 Kotlin 规则时，为 Web 和 Android 共用输入／期望输出样例。
- 明确用户输入归一化、可接受答案、特殊形式和无效输入行为。
- 新增本地持久化时定义 schema、版本、缺失字段默认值、损坏数据处理和错误提示。
- 仅在模块有可复习题目时接入全局错题；错题本需能根据模块 ID 返回正确模块。

### UI 与无障碍

- 沿用纸感品牌氛围与语义化颜色；不在组件中散落硬编码色值。
- Web 交互使用语义化元素、键盘焦点与适当的 `aria-*` 状态；支持输入法组字场景。
- Android 交互遵循系统返回、输入法、权限和页面生命周期约定。
- 新增功能需说明加载中、空、错误、离线和权限拒绝状态。
- 新模块导航项仅在功能可用时显示，不用不可操作的占位入口模拟已发布能力。

### 集成与测试

- 在 Web 外壳中登记入口、视图和模块摘要；必要时接入共享错题与每日活动。
- 在 Android 工程中实现对应原生入口和 Kotlin 领域逻辑；不复用 WebView 作为原生 UI。
- 为规则添加引擎单元测试；为页面入口、练习闭环和存储行为添加 UI／模块测试。
- 为跨端共同规则运行共用样例，避免 JavaScript 与 Kotlin 变形结果漂移。
- 样式更改运行样式契约测试；UI 结构更改运行 DOM 桩冒烟测试。
- 新增网页界面文字或日语词条后重建 `web/font/` 字体子集，并运行字体契约测试。

## Web 当前代码约定

- `web/verb-engine.js` 与 `web/adjective-engine.js` 是纯逻辑 UMD 模块；继续保持引擎不操作 DOM。
- `web/app.js` 负责状态、事件和渲染；新增 DOM 节点登记在集中管理的元素对象中。
- 颜色使用 `web/styles.css` 已定义的语义令牌；维护样式时运行 `web/tests/styles.test.js`。
- 本地存储以版本化 key 管理，读取和写入需显式处理解析、结构或访问错误。
- Node.js 内置 `node:test` 测试可在没有前端构建工具的情况下运行。
